sets source_map.disposition = 'excluded' with anilist_id NULL, deletes the ingest_afl_shows staging row, and
**deletes the `series` row whose id equals the slug** — with every cascade (episodes, chapter_anchors,
episode_annotations, series_components, series_external_ids, series_relations, watch_order_entries,
ingest_fractionals, episode_correspondence, series_arcs). The fixture index is stale, so all 27 "corrupt"
verdicts were false positives (index title "Death Note: Relight" for food-wars-second-plate-1, and so on).
The session ran it without reading it and without a dry run. That is the failure.

## The durable fix (capture, whichever option Sean picks)

- **No script deletes a series row except rebuild.ts under Sean's authorization** — a new rule: `exclude()`
  flips a disposition and drops staging, never canonical; a slug that matches a series id is a LISTING for a
  ruling. G57's principle ("a writer deletes only what it minted") extended to series rows.
- **The static fixture index is not an authority** (G44 / G51): audit-titles reads the LIVE staged index or
  is retired; the "corrupt" class becomes a census listing, never an action.
- **A tombstone ledger** — `series_ledger` (id, created_at, deleted_at) written by a DB trigger, so a cascade
  cannot erase the evidence and a census class `series_deleted_unruled` lists any deletion no ruling names.
- **Trap (apply-batch / discover skills):** an EVENT roster script is run ONLY on its trigger, after reading
  it, with `--dry-run` first when it has one and never when it does not; "I only wanted its side effect"
  is exactly how this happened.
